Visual Overhaul — Implementation Approach

How should we structure the work? Click the approach that makes sense.

A

Bottom-Up: Tiles → Buildings → Characters → Cues

Replace the visual layers from the ground up. Each layer builds on the previous one.

Step 1: Replace terrain rendering — swap colored tiles for Anokolisa tileset (grass, dirt, water, paths)
Step 2: Replace buildings — swap colored rectangles for Anokolisa house/farm/shop sprites
Step 3: Replace characters — swap colored circles for animated sprites (Anokolisa heroes + Superdark NPCs)
Step 4: Add visual cues on top — bubbles, mood icons, relationship lines, action indicators

Pros

  • Each step is independently testable
  • Visual cues designed after art is final — no rework
  • Natural dependency order

Cons

  • Visual cues come last — longest wait for the feature you originally asked for
  • Can't see how cues interact with art until the end
B

Parallel Tracks: Art Overhaul + Cue System Together

Design the cue system alongside the art. Both reference the same sprite sizes and palette.

Track A (Art): Tilemap → Buildings → Character sprites → Props/decoration
Track B (Cues): Conversation bubbles → Mood/need indicators → Action icons → Relationship visuals
Integration: Both tracks share sprite config (TILE_SIZE=16, scale factor, palette). Merge at the end.

Pros

  • Cues and art co-designed — guaranteed visual harmony
  • Can test cues early even with placeholder art
  • Faster overall delivery

Cons

  • If art decisions change, cues may need adjustment
  • Slightly more complex plan
C

Characters-First: Agents → Cues → World

Start with what the user sees most — the agents and their visual feedback. World art comes last.

Step 1: Replace agent sprites (Anokolisa + Superdark) with proper walk cycles
Step 2: Add all visual cues — bubbles, mood, relationships, actions
Step 3: Replace terrain tiles
Step 4: Replace building sprites

Pros

  • Biggest visual impact first — agents are what you watch
  • Visual cues come early
  • Can demo interesting agent behavior quickly

Cons

  • Pixel art agents on colored rectangles looks jarring temporarily
  • May need to adjust agent positioning when tiles change

My Recommendation: Approach A (Bottom-Up)

The visual cues (bubbles, indicators, icons) all need to be positioned relative to sprites and tiles. If we design them first and then change the art, we'll be adjusting offsets, sizes, and colors twice. Bottom-up means every layer is final when the next starts. The cues come last but they'll be right the first time.

The plan will be structured so each step is a shippable increment — you'll see progress at every stage, not just at the end.
