# Agent Agency: LLM-Driven Life Ambitions & Goals

## Problem

Agents feel aimless. The current goals system has 12 hardcoded types triggered by rules, but:
- Goals don't feed into daily planning (`PlanGenerator` passes `goals: []`)
- Goals don't influence decision scoring (`decisions.ts` has zero goal references)
- Aspirations are defined but barely integrated (shift triggers never evaluated, interaction biases unused)
- Priority formulas are dead strings (defined but never parsed)
- No multi-day persistence — goals abandon within hours
- Agents don't adapt when plans fail

## Solution

A two-layer goal system powered by LLM generation, mapped to existing interactions.

### Layer 1 — Life Ambition (1 per agent)

A persistent, concrete ambition generated by LLM from personality, memories, and circumstances.

Examples:
- "Become the wealthiest person in town"
- "Find true love and settle down"
- "Earn everyone's respect through hard work"
- "Live freely without anyone telling me what to do"

**Lifecycle:**
- Generated once on agent creation or first wake-up
- Re-evaluated only on major life events (heartbreak, bankruptcy, betrayal, major achievement)
- Shifts are rare — maybe once per in-game week
- Stored in repurposed `aspirations` table

**Replaces:** The current 8-type aspiration system (wealth, love, power, etc.) which is defined but non-functional.

### Layer 2 — Active Goals (1 life ambition + up to 3 active goals)

Concrete, actionable goals generated by LLM each morning during the planning pipeline.

Examples:
- "Convince Elena to go on a date this week"
- "Save enough money to buy the empty shop"
- "Find out who has been stealing from the market"

**Lifecycle:**
- Generated each morning if goal slots are available
- Derived from: life ambition + memories + relationships + personality + economy
- Each goal is mapped to existing interaction types via GoalMapper
- Persist across days — re-evaluated each morning (continue / adjust / abandon)
- On failure: LLM attempts one pivot before abandoning
- On completion: reflection memory + potential ambition progress

**Coexists with:** Existing reactive triggers (`GOAL_TRIGGER_REGISTRY`). State-driven goals (angry→revenge, heartbroken→comfort) still fire via rules as immediate emotional reactions. LLM handles proactive goal generation.

**Slot allocation:** `MAX_GOALS_PER_AGENT` increases from 3 to 4. LLM goals run first at morning (can fill up to 3 slots). Reactive triggers can fill remaining slots throughout the day, up to the cap of 4. This ensures reactive emotional goals (angry→revenge) always have room to fire even if the LLM filled 3 slots. If all 4 are full, reactive triggers are suppressed until a slot opens.

### Migration Defaults

All new columns use defaults so existing data remains valid:
- `goals.description` → defaults to `goal.type` (e.g. "revenge") for existing rows
- `goals.strategy` → defaults to null
- `goals.mapped_interactions` → defaults to the `valid_interactions` from `GOAL_REGISTRY[goal.type]` serialized as JSON
- `goals.pivot_count` → defaults to 0
- `goals.source` → defaults to `"reactive"` for existing rows
- `aspirations.description` → defaults to the `ASPIRATION_REGISTRY[type].description` for existing rows
- `aspirations.shifted_reason` → defaults to null

Migration script populates these defaults for any existing active goals/aspirations at startup.

## New Modules

All in `server/lib/goals/`:

### `GoalReviewer.ts`
- Called at the top of `goalsTick()` on day-change ticks, before `evaluateAbandonment()` runs
- This ensures LLM review happens before rule-based abandonment, preventing conflicts
- Emits `ambition:shifted` event when life ambition changes
- Single LLM call per agent with structured JSON output
- Input context: life ambition, active goals (with progress), recent memories (last 2 days), personality summary, relationship highlights, economy state
- Output schema:
```json
{
  "ambition": "keep" | { "shift": "new description", "category": "wealth|love|power|...", "reason": "..." },
  "reviews": [
    { "goal_id": 1, "action": "continue" | "adjust" | "abandon", "reason": "...", "new_strategy?": "..." }
  ],
  "new_goals": [
    { "description": "...", "target_agent": "Elena" | null, "category_hint": "romantic", "strategy": "...", "priority": 0.7 }
  ]
}
```
- Max context: ~2000 tokens input, ~500 tokens output

### `GoalMapper.ts`
- Maps free-form LLM goals to existing interaction types
- Input: `{ description, target_agent?, category_hint }`
- Output: `{ type, mapped_interactions: string[], target_id?: number }`
- Mapping logic:
  1. Use `category_hint` to select interaction family
  2. Category → interaction mapping:
     - "romantic" → `["flirt", "date", "hookup", "compliment"]`
     - "hostile" → `["fight", "spread_rumor", "vandalism", "blackmail", "pickpocket"]`
     - "social" → `["comfort", "buy_drinks", "lend_money", "befriend"]`
     - "economic" → `["work"]` (location-based)
     - "investigative" → `["eavesdrop", "interrogate"]`
     - "protective" → `["comfort", "nurse", "lend_money"]`
     - "custom" → union of all social + economic interactions: `["comfort", "buy_drinks", "lend_money", "befriend", "work", "eavesdrop"]`
  3. Resolve agent names to IDs via DB lookup. If name doesn't match exactly, use case-insensitive substring match. If still no match, set `target_id` to null and log a warning — goal can exist without a target.

### `goalPrompts.ts`
- Prompt templates for:
  - Morning goal review & generation
  - Goal pivot attempt
  - Initial life ambition generation
- All prompts include personality summary and relevant memories
- Structured JSON output format with fallback parsing

### `goalParser.ts`
- Robust parser for LLM JSON output (following `reflectionParser` and `planParser` patterns)
- Handles malformed JSON, missing fields, partial responses
- Returns typed objects or null on failure

### `PivotEvaluator.ts`
- Checks if a goal is stale (no progress for `PIVOT_THRESHOLD_TICKS` = 1440 ticks / ~1 day)
- Also checks if goal target is dead/inactive → auto-abandon with emotional consequences scaled by relationship closeness
- If `pivot_count === 0`: triggers LLM pivot call
  - LLM receives: goal description, strategy, what was tried, why it didn't work
  - LLM outputs: new strategy + possibly new mapped_interactions
  - Updates goal in DB with new strategy, increments pivot_count
  - Emits `goal:pivoted` event
- If `pivot_count === 1`: abandons goal with emotional consequences
- Called from `goalsTick()` after existing abandonment evaluation

### `instance.ts`
- Singleton instances of GoalReviewer, GoalMapper, PivotEvaluator

## Integration Points

### 1. Goals → Planning (`PlanGenerator.ts`)

Current (broken):
```typescript
goals: [], // Line 207
```

Fixed:
```typescript
// Load active goals for this agent
const activeGoals = db.select().from(goals)
  .where(and(eq(goals.agent_id, agentId), eq(goals.status, 'active')))
  .all();
goals: activeGoals.map(g => `${g.description} (strategy: ${g.strategy})`),
```

The plan prompt already renders goals as a numbered list. Agents will naturally allocate time blocks for goal pursuit.

### 2. Goals → Decisions (`decisions.ts`)

Add goal alignment scoring in the free-time action evaluation:

```typescript
// Pre-load all active goals into a Map at tick start (alongside needsMap, econMap):
const allGoals = db.select().from(goals).where(eq(goals.status, 'active')).all();
const goalsMap = new Map<number, typeof allGoals>();
for (const g of allGoals) {
  const arr = goalsMap.get(g.agent_id) ?? [];
  arr.push(g);
  goalsMap.set(g.agent_id, arr);
}

// Then in free-time scoring:
const agentGoals = goalsMap.get(agent.id) ?? [];
for (const goal of agentGoals) {
  const mapped = JSON.parse(goal.mapped_interactions ?? '[]') as string[];
  // If agent is at the same location as their goal target
  if (goal.target_id) {
    const target = activeAgents.find(a => a.id === goal.target_id);
    if (target && agent.current_location === target.current_location && mapped.length > 0) {
      score += 2500 * goal.priority;
    }
  }
  // If agent is at a work location and has economic goal
  if (goal.type === 'economic' && agent.current_action === 'working') {
    score += 1500 * goal.priority;
  }
}
```

Priority hierarchy preserved: emergency (9999) > plan (6000) > goal-aligned (2500-4500) > free-time (variable) > idle.

### 3. Goals → Memory (`MemoryObserver`)

Update existing `goal:created`, `goal:completed`, `goal:abandoned` handlers to use `description` field (free-form) instead of just `goalType` string. Add new handlers for new events:

- `goal:created` → memory: "I've decided to [description] because [motivation]" (update existing handler)
- `goal:completed` → memory with positive valence: "I accomplished [description]." (update existing handler)
- `goal:abandoned` → memory with negative valence: "I gave up on [description]. [reason]" (update existing handler)
- `goal:pivoted` → memory: "My approach to [description] wasn't working. I'm going to try [new strategy] instead." (**new** handler)
- `ambition:shifted` → high-importance memory: "I used to want [old]. Now I want [new] because [reason]." (**new** handler)

### 4. Goals → Conversations

When building conversation context (`ContextBuilder`), include active goals so agents naturally bring them up:
- "I've been trying to [goal description]"
- Agents with shared targets or complementary goals have richer conversations

### 5. Morning Wake-Up Hook

Execution order within `goalsTick()` on day-change ticks:
1. `GoalReviewer.review(agentId)` runs first — single LLM call, processes ambition shifts + goal reviews + new goal creation
2. `evaluateAbandonment()` runs second — rule-based checks on remaining goals (LLM goals with type "custom" skip this since they're not in `GOAL_REGISTRY`; they rely on the morning LLM review and `PivotEvaluator` for lifecycle management)
3. `evaluateTriggers()` runs third — reactive triggers fill remaining slots (up to `MAX_GOALS_PER_AGENT` = 4)
4. `PivotEvaluator.evaluate()` runs last — checks for stale goals, triggers pivots or abandonment

Then `PlanGenerator` runs with actual goals loaded (fixing `goals: []`).

### 6. Goal Failure → Emotional Consequences

When a pivoted goal is finally abandoned:

```
importance = goal.priority × daysActive × personalityFactor
```

Where `personalityFactor`:
- Neurotic agents: × 1.5 (feel failures deeply)
- Impulsive agents: × 0.7 (move on quickly)
- Base: × 1.0

If importance > 0.6:
- Neurotic: trigger "stressed" or "depressed" state
- Aggressive: trigger "angry" state (may cascade to new revenge goal via reactive triggers)
- High warmth: trigger "lonely" or "sad" reflection

If importance ≤ 0.6:
- Reflection memory only, no state change

### 7. Aspiration Shift Evaluation

On major life events (emitted via `simEvents`):
- `relationship:ended` → evaluate ambition shift if ambition is "love"
- `economy:bankrupt` → evaluate ambition shift if ambition is "wealth"
- `goal:completed` (high-priority) → increment hidden ambition progress
- `state:gained` (dramatic: arrested, heartbroken) → evaluate shift

Shift evaluation is a lightweight LLM call (~200 tokens) that asks: "Given what just happened, does [agent] still want [ambition], or has their perspective changed?"

## LLM Budget

| Call | When | Per agent/day | Total/day (12 agents) |
|------|------|---------------|----------------------|
| Morning goal review + generation | Wake-up | 1 | 12 |
| Goal → plan integration | Wake-up | 0 (merged) | 0 |
| Pivot attempt | On stale goal | 0-0.5 | 0-6 |
| Ambition shift evaluation | Major events | 0-0.2 | 0-2 |
| Completion/abandonment memory | On resolve | 0 (no LLM, template) | 0 |
| **Total new calls** | | **~1.2-1.7** | **~12-20** |

Added to existing ~130-200 calls/day = ~142-220 total. Well within Gemma 4 26B MoE throughput on RTX 3090.

## What Gets Removed

- `GOAL_TRIGGER_REGISTRY` proactive triggers (`aspiration_pressure`, `relationship_threshold`) — replaced by LLM generation
- Reactive triggers (`state_gained`, `fact_learned`) — **kept as fallback**
- `ASPIRATION_REGISTRY.shift_triggers` — replaced by LLM-driven shifts
- `ASPIRATION_REGISTRY.interaction_biases` — replaced by goal `mapped_interactions`
- `ASPIRATION_REGISTRY.goal_affinity` — replaced by LLM understanding of ambition→goal alignment
- `priority_formula` strings — replaced by LLM-assigned priority
- `evaluateTriggers()` proactive path — simplified to reactive-only

## What Gets Kept

- `GOAL_REGISTRY` goal definitions (valid_interactions, progress_events) — used by GoalMapper
- `GOAL_TRIGGER_REGISTRY` reactive triggers (state_gained → revenge, etc.) — emotional reactions
- `evaluateAbandonment()` — rule-based abandonment still runs for goals with types in `GOAL_REGISTRY`; LLM "custom" goals skip this (managed by GoalReviewer + PivotEvaluator). Safety net: any goal (regardless of type) older than 4320 ticks (~3 days) with zero progress is auto-abandoned.
- `evaluatePassiveProgress()` — passive goals (pay_debt, get_sober) still work
- All interaction→goal progress mechanics — unchanged
- `goalsTick()` structure — extended, not replaced
